# Safeer Backend — Deep Code Review (C-items)

**Repo:** `safeer_api` @ `c0147c1` · **Date:** 2026-09-26
**Scope:** every file in `src/` (252 files, ~14.7k lines), `migrations/`, `scripts/`, `tools/`, CI, env and deployment docs. Four parallel reviews, one per area: auth/infra, scholarship workflow, content/CMS, data/ops. I then re-checked the highest-severity findings against the code.

This extends `docs/safeer-backend-fr-review.md`. The FR review checked **what** exists against the spec (B1–B19). This review checks **how well it's built**. None of the C-items below duplicates a B-item.

**Verdict:** the architecture is sound, and many things are already done right:
- separate staff and applicant sessions
- CSRF, and a constant-time compare on the CSRF token
- a last-admin lock
- strict DTOs, so no mass assignment
- DOMPurify on markdown
- file types checked from their content (magic bytes)
- ownership checks on private files
- slot booking locked against double booking
- reference numbers taken from a locked counter
- AES-GCM with a random IV
- no drift between the entities and the SQL schema
- every mail/SMS key has templates in both languages

But **12 High issues** would cause real harm in production and must be fixed before launch.

## High — fix before launch

| ID | Issue | Where | Fix |
|---|---|---|---|
| **C1** | **OTP codes stored in plain text.** The `otp_code` mail **subject** contains `{{code}}`, and `mail_log.subject` stores it. `sms_log.message` stores the full SMS. Both logs are readable through `GET /admin/mail/log` and `/admin/sms/log`, `sms_log` is never purged, and both end up in backups. Anyone with admin or DB access can use a live code. | `002_seed.sql:126,129`, `mail.service.ts`, `sms.service.ts:62,83` | Take `{{code}}` out of the subject. Store a masked body (`••••••`) for `otp_code` in both logs. Smoke tests read codes from a dev-only hook, never from the logs. |
| **C2** | **Every emailed link 404s.** `PUBLIC_BASE_URL` is the API's URL (`.env.example:30`), but it's used to build frontend pages (`/admin/accept/:token`, `/admin/reset/:token`, `/portal`, `/admin/messages`). No invite can ever be accepted. | `auth.service.ts:229,268`, `applications.service.ts`, `portal-*`, `messages.service.ts` | Add `FRONTEND_BASE_URL`. Build locale-aware frontend links: `/{locale}/admin/accept/{token}`, `/{locale}/admin/reset/{token}`, `/{locale}/portal/login`, `/{locale}/admin/messages/{id}`. |
| **C3** | **Disabling a staff user doesn't stick.** `isLocked` is both "admin disabled" and "brute-force locked". `resetPassword` and `acceptInvite` set `isLocked=false`, so a disabled user can unlock themselves with forgot → reset. Unlocking doesn't reset `failedLogins`. Consuming one token leaves the user's other tokens valid. Email change or disable doesn't invalidate tokens. `forgotPassword` also works for users with a pending invite. | `auth.service.ts:244,288`, `users.service.ts:121,127` | Add a `status` column (`active \| disabled \| invited`) separate from the brute-force lock. Refuse forgot/reset/accept for `disabled`. Delete all of a user's tokens on disable, email change or token use. Reset `failedLogins` when an admin unlocks. |
| **C4** | **`login()` saves the whole user row.** This rewrites `passwordHash` (a `select:false` column) and `isLocked` from a stale copy. A login in flight can undo a password reset or an admin disable, and parallel failures lose `failedLogins` increments. | `auth.service.ts:114-116,334-339` | Use targeted atomic `UPDATE`s: `failed_logins = failed_logins + 1`, and success-path updates guarded by `is_locked = 0`. |
| **C5** | **CSV formula injection.** Names and universities typed by applicants go into `export.csv` unneutralised (`=HYPERLINK(...)`, DDE). | `common/csv.ts:12-17` | Prefix `'` to values that start with `= + - @ \t \r`, then quote them. |
| **C6** | **Two staff status changes can race.** Both check the transition, both save and notify, so the applicant receives both "accepted" and "rejected", and the last write wins. This applies to single, bulk and request-documents actions. | `admin-applications.service.ts:300-320,385,427` | Use a transaction with `pessimistic_write` (or `UPDATE … WHERE status = :from` and check the affected rows). Notify only after commit. |
| **C7** | **Original photos are served publicly with EXIF/GPS.** The original bytes are stored untouched and streamed from `/files/:publicId`. The variants also ignore EXIF orientation, and `widthPx`/`heightPx` are the values before rotation. | `media.service.ts:105`, `image-pipeline.ts:66-78`, `files.controller.ts:62` | Re-encode the original with `sharp(...).rotate()`, which strips metadata. Use `autoOrient` and store the dimensions after rotation. Backfill existing assets in a script. |
| **C8** | **`db:reset` and `smoke` can wipe production.** The guard only checks for `DB_HOST=127.0.0.1`, which is exactly what production uses on Hostinger. `smoke` creates staff with a known password and deletes data. | `scripts/db-reset.mjs:36-40`, `scripts/smoke.mjs` | Allow only `NODE_ENV ∈ {development, test}`, plus a `--confirm=<dbname>` flag. |
| **C9** | **Expiry comparisons mix clocks.** JS `Date` values are written in the Node process's local zone, but compared with MySQL `NOW()` in the DB zone. With a mismatch, OTP codes, reset links, invites and sessions last 3h too long, or are already expired when issued. | `database.module.ts:38-51`, `session.guard.ts:103,165`, `auth.service.ts:315`, `portal-otp.service.ts:128` | Set `timezone: 'Z'` and `SET time_zone='+00:00'` on every connection (app, data-source, migrate), or pass `:now` from JS everywhere. |
| **C10** | **Unsafe URLs are stored and shown publicly.** `primaryButtonUrl`/`secondaryButtonUrl`, partner `url` and the social URLs accept `javascript:` (zod `.url()` does too), so an **editor** can plant stored XSS. Redirect rows accept `//evil.com` or `https://…` (an open redirect), `from === to`, and chains. | `page.dto.ts:35,38`, `partner.dto.ts:9`, `site-settings.dto.ts:18-20`, `redirect.dto.ts:6-7` | A shared `safeUrl` refinement: `https:` / `http:` / `mailto:` / `tel:`, or a relative `/path`. Redirects: both paths must match `^/(?!/)`, be different, and not form a chain. |
| **C11** | **Dev fixtures load on anything that isn't exactly `production`.** `NODE_ENV=prod` or `Production` loads fake applicants and published fake partners into production. | `scripts/migrate.mjs:51` | Load dev fixtures only when `NODE_ENV ∈ {development, test}`, and validate `NODE_ENV` against the `env.ts` enum. |
| **C12** | **Anyone can lock out every admin.** `failedLogins` never decays, and 10 failures lock the account **and revoke its sessions**. About 10 requests per admin email locks the whole staff out, again and again. | `auth.service.ts:334-349` | Use a time-boxed lockout (15 min with backoff). Don't revoke sessions on a brute-force lock. Admin-disable is separate (C3). |

## Medium

| ID | Issue | Where | Fix |
|---|---|---|---|
| **C13** | `publishRules` is skipped on **create**, so `POST /admin/news {isPublished:true}` publishes a post with no cover. `publishedOn` can be null on publish, which puts the post last in the feed. The seeded post is already published with no cover, so its first edit returns 409. The audit log records `create`/`update` instead of `publish`. | `crud.factory.ts:294-307`, `post.dto.ts`, `002_seed.sql:97` | Run `publishRules` on create. Default `publishedOn` to today on publish. | **C14** | **Slug handling.** Renaming a slug back (A→B→A) creates a permanent `/news/A → /news/A` self-redirect, and the `redirects` cache tag isn't purged. New slugs aren't checked against existing redirects. Slugs aren't validated (spaces, `/`, uppercase). The slug `featured` collides with `/news/featured`. A long title plus `-2` overflows `varchar(191)` and gives a 500. Editors can rename system page slugs (`home`, `about`, …), which breaks home and the nav. | `crud.factory.ts:439-445`, `slugify.ts`, `post.dto.ts:30`, `page.dto.ts:6` | Inside the transaction, delete redirects whose `from_path` is the new live path, and skip `from = to`. | **C15** | **The applicant can rewrite the whole submitted form while in `docs_missing`** (name, ID, email, phone…) with no event or audit. Any correction in `docs_missing` goes through a whitelisted endpoint that writes a visible event. |
| **C16** | **Our emails can be used for phishing.** `POST /applications` and `/contact` send branded mail to an **unverified** address. GFM autolinks URLs typed into `firstName`/`lastName`/`name`, so an attacker gets a clickable phishing link inside a genuine Safeer email. | `applications.service.ts:124-134`, `contact.service.ts:62-68`, `render-template.ts` | Restrict name fields to letters, spaces, `'` and `-`. | **C17** | **The interview flow is incomplete.** The applicant can't see their booked slot. Open slots are still listed after booking, and a second booking returns a generic 409. Past slots can be booked. There's no cancel or reschedule, and no confirmation mail/SMS. Slots don't enforce `endsAt > startsAt`. A booked slot can be edited without telling the applicant. | `portal-interview.service.ts`, `portal-application.service.ts`, `interview-slot.dto.ts` | Add `interview: {startsAt, endsAt, location} \| null` to `/portal/me`. Return an empty slot list once booked. Filter out past slots (`startsAt > NOW()`). Map the duplicate to `SLOT_ALREADY_BOOKED`. Add `DELETE /portal/interview` (cancel/reschedule, locked). Send confirmation mail/SMS. Validate slot times. Notify the applicant on a booked-slot change, or block the change. |
| **C18** | **Replaced uploads are never deleted, and uploads have no throttle.** One session can fill the disk at about 500 MB/min. | `portal-documents.service.ts:62-86` | Add `@Throttle` (20/h) and a per-application quota (e.g. 30 files / 50 MB). Delete superseded files after commit. |
| **C19** | **Arabic filenames break.** busboy decodes them as latin1 (mojibake), and a correctly decoded Arabic name makes `Content-Disposition` throw `ERR_INVALID_CHAR`, so the download fails with a 500. | `portal-documents.controller.ts:25,37`, `admin-applications.controller.ts:94` | Use `defParamCharset:'utf8'` (or re-decode). Send an ASCII fallback plus `filename*=UTF-8''…`. |
| **C20** | **The overview ignores the role matrix** (this extends B6). `support` still gets application counts and applicant names. The audit feed sends raw `diff`s to every role. | `admin-overview.service.ts:57,154` | Use `includeApplications = role ∈ {admin, reviewer}`. Make the audit feed admin-only, with no `diff`. |
| **C21** | **The SMS HTTP driver has no timeout and is awaited inside requests.** OTP, submit, status changes and bulk (200× in sequence) all hang if the provider is slow, and the latency also leaks whether an identifier exists. | `sms-transport.service.ts:45`, `sms.service.ts:76` | Use `AbortSignal.timeout(5000)`, and queue SMS fire-and-forget the way mail already is. |
| **C22** | **The OTP guess budget resets.** Every request mints a new code with `attempts = 0`, and the reference and the email are separate limiter buckets. That allows about 50 guesses per 15 min, the limiter is in memory only, and a victim can be locked out. | `portal-otp.service.ts:74-85,132,166-173` | Rate-limit per `application.id`. Keep a daily failure counter in the DB (lock after 10). Invalidate older codes when a new one is issued. |
| **C23** | **Notifications show raw codes.** Arabic mail/SMS show `under_review` and `id_copy`. `user_invite` uses `{{role}}`, which is never passed. `note` is always empty. `contact_notify`'s subject shows a raw enum. Arabic HTML mail has no `dir="rtl"` wrapper. | `admin-applications.service.ts:332,341,446,516`, `auth.service.ts:233`, `mail-templates.service.ts:79` | Pass localized labels (ar/en maps keyed by `application.locale`). | **C24** | **`?preview=` skips the cache on any route, whatever the token.** `GET /home?preview=1` is also `@SkipThrottle`, which makes it an easy way to overload the database. | `cache.interceptor.ts:83` | Bypass only on routes marked preview-capable, and only after the token verifies. |
| **C25** | **Public files stay public after they're unpublished.** They're sent with `public, max-age=31536000, immutable`, so browsers and CDNs keep them for a year. Documents in an **unpublished category** stay downloadable. | `files.controller.ts:101`, `media.service.ts:270` | Short `max-age` (300 s + SWR) for originals and PDFs. Join `doc_categories.is_published` in the public-readable check, and add `doc_categories` to the memo purge tags. |
| **C26** | **Page-section and about-item bodies go out as raw markdown**, while news bodies are rendered and sanitized. That's inconsistent, and a stored-XSS risk if the frontend renders them. | `public-page.ts:32`, `public-home.ts:49` | Render them with `MarkdownService` like news, and document that these fields are sanitized HTML. |
| **C27** | **Personal data is never purged**: contact messages, `sms_log`, unsubscribed newsletter rows, abandoned drafts and their files. There's no way to unsubscribe (`unsubscribed_at` can never be set), no double opt-in, and no admin delete or anonymise for applications. | `maintenance.service.ts`, `contact/*` | Retention jobs, e.g. contact 24 months, sms_log 90 days, drafts idle 180 days together with their files. | **C28** | **National IDs are stored in plain text, and backups aren't encrypted.** The documented `mysqldump` lacks `--single-transaction`, puts the password on the command line, runs at the same time as the maintenance job, and has no offsite copy. | `001_schema.sql:634`, deployment doc | Encrypt `id_number` with AES-GCM (`APP_ENCRYPTION_KEY`), with a migration to backfill existing rows. | **C29** | **Migration runner.** It keeps no checksum, so an edited `002` or `003` silently never applies. A file that fails halfway can't be retried (DDL auto-commits, and there's no `IF NOT EXISTS`). There's no run lock. The least-privilege `DB_USER` can't run migrations, and `safeer_app@'%'` is reachable from any host. | `scripts/migrate.mjs`, `create-app-db-user.sql` | Store a sha256 per file and fail on mismatch.
